Build a polished, functional proof-of-concept for a custom gym management platform for WAKA, a three-branch gym business in Kigali, Rwanda.

PROJECT NAME
WAKA Management Platform — Phase 1 POC

IMPORTANT CONTEXT

WAKA currently uses Fitbase, but staff have reported several operational problems:

- unreliable card check-in
- cases where the speedgates fail simultaneously
- new cards sometimes taking approximately four hours before becoming active
- failed or unreliable membership renewal reminders

The long-term goal is to build an independent WAKA-owned platform rather than moving to another paid gym-management SaaS.

Fitbase should eventually only be needed as a source for migrating existing member records.

WAKA currently has THREE branches.

IMPORTANT:
Only ONE of the three branches currently has physical speedgates.
The other two branches currently rely on reception/manual check-in and should NOT be represented as having speedgates.

The eventual platform should support:

- memberships
- payments
- self-service renewal
- member accounts
- card/credential management
- branch check-ins
- access control
- notifications
- automation
- reporting
- offline-capable access at the gated branch
- future integration with physical speedgates

This Phase 1 project is a POC.

Do NOT pretend that real integrations already exist.

Clearly label simulated integrations as SIMULATED.

No real payment processor, SMS provider, WhatsApp API, Fitbase API, or physical speedgate needs to be connected yet.

The purpose of this version is to convincingly demonstrate how the final system would work.

This project will initially be developed using Replit, BUT production will NOT be managed or hosted through Replit.

After the POC, the entire codebase will be downloaded/exported, placed in a Git repository, and eventually deployed to a VPS or cloud server using Docker.

Therefore:

DO NOT tightly couple the application to Replit-specific infrastructure.

The project should be portable.

It should be possible to eventually run something like:

git clone <repository>
docker compose up -d

on an ordinary Linux VPS.

Avoid proprietary Replit dependencies wherever practical.

Use environment variables for configuration.

Do not hardcode production credentials.

Do not use Replit-specific authentication as the application's primary authentication architecture.
